## What is bobbie?

<p align="center">
<img src="https://media2.giphy.com/media/v1.Y2lkPTc5MGI3NjExcG00NThjdWpoamJ1N2kyajU1YjBkc2VjNzVsYjY3dmcwaHo1cTFjayZlcD12MV9pbnRlcm5hbF9naWZfYnlfaWQmY3Q9Zw/26gstFhO0hBFQcfOE/giphy.gif" alt="It's better to know what you want and who you are" style="width:400px;"/>
</p>

Named after [Roberta Draper ("Bobbie")](https://expanse.fandom.com/wiki/Bobbie_Draper_(TV)) from ["The Expanse,"](https://www.amazon.com/The-Expanse-Season-1/dp/B08B48L4CQ) `bobbie` provides
a lightweight and easy-to-use way to store and access configuration settings for a Python project.

## Why use bobbie?


<p align="center">
<img src="https://media4.giphy.com/media/v1.Y2lkPTc5MGI3NjExcGU5Z2pzZGg3c3p0c3g4c3J1MXdtb3lobnQ4OXR4aGxhajl2a2NqbCZlcD12MV9pbnRlcm5hbF9naWZfYnlfaWQmY3Q9Zw/coCeBe4qutRaMQ51cH/giphy.gif" alt="It's better to know what you want and who you are" style="width:300px;"/>
</p>

There are [numerous options](#similar-projects) for storing configuration settings in Python.
So, what makes `bobbie` different?

* **Flexible**: a `Settings` instance is easily built from a `dict`, Python module, or file (ini, json, toml, and yaml formats are supported).
* **Lightweight**: an efficient codebase ensures a very small memory footprint.
* **Intuitive**: a `create` class method constructs `Settings` (from any data source).
* **Portable**: `Settings` can be exported to any of the supported file types, so
  settings built in code can be saved as a settings file.
* **Convenient**: unlike `configparser`, values stored as strings (such as in
  `ini` files) are automatically converted to the matching Python types when
  `Settings` is created.

The [comparison table](#feature-comparison-of-python-configuration-libraries)
below shows how `bobbie` compares to the other major options that store
configuration options for Python projects.

### Installation

To install `bobbie`, use `pip`:

```sh
pip install bobbie
```

Loading and exporting `yaml` files requires the `yaml` extra, which adds
[`PyYAML`](https://pypi.org/project/PyYAML/). Exporting `toml` files
requires the `toml` extra, which adds
[`tomli-w`](https://pypi.org/project/tomli-w/):

```sh
pip install "bobbie[toml,yaml]"
```

### Create a Settings instance

`bobbie` supports several ways to create a `Settings` instance. You can either:
* If the settings are in a file, call a class method specific to the file type (`from_yaml` in the second example below);
* Call a class method for the general type of source data (`from_dict` or `from_file`);
* Call the `create` class method and it will automatically figure out the appropriate constructor; or
* If the settings data is in a `dict`-like object, pass it as the first argument to `Settings`.

#### From a `dict`

```python
import bobbie

configuration = {
  'general': {
    'verbose': False,
    'seed': 43,
    'parallelize': False},
  'files': {
    'source_format': 'csv',
    'file_encoding': 'windows-1252',
    'float_format': '%.4f',
    'export_results': True}}
# You can pick a specific constructor method.
settings = bobbie.Settings.from_dict(configuration)
# Or, may use the general `create` method.
settings = bobbie.Settings.create(configuration)
# Or, just send a `dict` to `Settings` itself.
settings = bobbie.Settings(configuration)
```

#### From a file

```python
import bobbie

# You may use the general `create` method.
settings = bobbie.Settings.create('settings_file.yaml')
# Or, the `from_file` method.
settings = bobbie.Settings.from_file('settings_file.yaml')
# Or, the `from_yaml` method. They all do the same thing.
settings = bobbie.Settings.from_yaml('settings_file.yaml')
```

If the file is a Python module, it must contain a variable named `settings` in the module namespace
(unless you [change the global setting](https://WithPrecedent.github.io/bobbie/advanced/#global-options)
for the variable name).

#### Type inference

`ini` and `json` files often store numbers, booleans, and lists as strings, so
`bobbie` converts their values to the matching Python types:

* `'42'` becomes `42` and `'2.5'` becomes `2.5`.
* `'true'`, `'yes'`, `'false'`, and `'no'` (in any case) become `True` or
  `False`.
* `'[x, y, z]'` and `'x, y, z'` become `['x', 'y', 'z']`. A comma followed by
  a line break also splits a list, so a list can span several lines of an
  `ini` file, but a comma with nothing after it, as in `'x,y'`, does not
  split a string.
* `'{a: 1, b: [x, y]}'` becomes `{'a': 1, 'b': ['x', 'y']}`.

Items in lists and dicts are converted the same way and may be nested. Put an
item in quotes (such as `["a, b", '1']`) to keep it as a string.

`toml`, `yaml`, and Python module values are not converted because those
formats already store their own types. So, a `toml` value of `"[a, b]"` stays a
string. See the [Advanced User Guide](https://WithPrecedent.github.io/bobbie/advanced/#type-inference-rules)
for the exact rules and how to turn inference on or off for each file type.

### Export settings to a file

`bobbie` can also create a settings file from a `Settings` instance. You can
either:
* Call the method specific to the file type (`to_ini`, `to_json`,
  `to_module`, `to_toml`, or `to_yaml`); or
* Call the `to_file` method and it will pick the appropriate method from the
  file extension.

```python
import bobbie

settings = bobbie.Settings.create('settings_file.yaml')
settings.add('general', {'seed': 7})
# You may use the general `to_file` method.
settings.to_file('settings_file.toml')
# Or, the `to_toml` method. They both do the same thing.
settings.to_toml('settings_file.toml')
```

Any additional keyword arguments are passed to the writer for the file type
(such as `indent` for `json.dump`). An existing file is overwritten.

Exported files can be loaded back into the same `Settings`. For `ini` files,
lists and dicts are written in the form that [type inference](#type-inference)
reads (such as `[x, y, z]`), and items that would otherwise be converted are
quoted. Because `ini` files store everything as strings, every top-level value
must be a section (a `dict`), and a string that looks like another type (such
as `'42'`) is loaded as that type. A `Settings` exported with `to_module`
stores its values in a module-level variable named `settings`. See the
[Advanced User Guide](https://WithPrecedent.github.io/bobbie/advanced/#writer-arguments)
for the arguments each exporter accepts and the other `ini` limits.

As you can see, `bobbie` lacks a method for storing passwords, encryption keys,
and other secrets. That is because it is focused on internal Python
projects and the goal of keeping its resource usage as low as possible. So, if
you need secrets stored in your project settings, there are several good options
linked above that you should explore.
